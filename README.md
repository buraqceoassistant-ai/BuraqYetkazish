# Логистика — отгрузки и клиенты (BURAQ logistics)

Сайт и мобильное приложение (PWA) для журнала отгрузок: клиенты, карта точек, дашборд, отчёты,
планы маршрутов A/B/C, тарифы и проверка данных. Работает на компьютере и на телефоне,
ставится на главный экран как обычное приложение и открывается без интернета.

Вход по логину и паролю. Данные хранятся на сайте только в зашифрованном виде.

## Разделы сайта

| Вкладка | Что внутри |
| --- | --- |
| **Журнал** | Отгрузки по партиям, по группам «машина · рейс» с итогом рейса (или по районам, или без групп), «+ вторая партия»; кнопка «Импорт манифеста» открывает импорт, плашка — черновики, которые ждут проверки |
| **Клиенты** | Справочник клиентов и складов |
| **Карта** | Точки партии и планы на карте |
| **Отчёты** | Подвкладки: Дашборд · Партия на день · Расходы · Автопарк · Водители · ИИ-отчёт (открывается на дашборде) |
| **Планы A/B/C** | Планы маршрутов; «Принять план» записывает машины в журнал и предлагает сразу отправить груз водителям |
| **Водители** | Большая кнопка «Отправить груз водителям», список водителей, заявки, «Кто что везёт», «Лента доставок» |
| **Визуализация** | Загрузка машин в 3D |
| **Настройки** | Подвкладки: Тарифы и планы · Водители и автопарк (бот, диспетчер, машины, госномера) · Связь (Google Таблица, ИИ, Telegram) · Проверка данных |

**Обновление страницы** возвращает туда, где вы были: вкладка и подвкладка, выбранный план (A, B, C, X) и партии в
журнале, планах, на карте и у водителей (`NAV_KEY` в `index.html`, хранится в `sessionStorage` этой вкладки браузера).
Партии, которых после обновления уже нет, заменяются последней, как раньше. Новое окно или новый запуск приложения
открывается с «Журнала».

## Вход и защита данных

- Excel с данными и общие настройки сайта (ссылка на Google Таблицу) зашифрованы случайным
  ключом (AES-256-GCM) и лежат в `data/vault.json`.
- Для каждого пользователя этот ключ зашифрован ключом из его пароля
  (PBKDF2-SHA256, 600 000 итераций). Логины хранятся только как хэши.
- Пароль никуда не отправляется: расшифровка идёт в браузере. Без пароля
  `vault.json` бесполезен, даже если его скачать из публичного репозитория.
- «Запомнить на этом устройстве» сохраняет ключ в браузере, и вход не спрашивается снова.
- «Аккаунт → Выйти» стирает с устройства ключ, локальную копию данных и настройки связи
  с Google Таблицей и Excel. Правки, не записанные в Excel или Таблицу, пропадают:
  перед выходом нажмите «Скачать Excel».

Защита держится на стойкости пароля: используйте сгенерированные пароли (как ниже),
а не короткие и простые.

Открытые данные (`*.xlsx`, `*.csv`) в репозиторий не коммитятся: это запрещено в `.gitignore`,
а сборка сайта падает, если найдёт `.xlsx`.

### Смена пароля на сайте

**Аккаунт → Сменить пароль**: введите текущий пароль, новый (не короче 8 символов) и GitHub-токен.
Сайт проверит текущий пароль, зашифрует ключ новым паролем и сохранит `data/vault.json`
в репозиторий. Через 1–2 минуты GitHub пересоберёт сайт, и новый пароль заработает везде.

Если пользователь на сайте один, при смене пароля меняется и ключ данных: старый пароль
не откроет данные даже из старых версий файла в истории репозитория, а на других
устройствах нужно будет войти заново. Если пользователей несколько, меняется только
пароль того, кто его сменил.

**GitHub-токен** нужен, чтобы сайт мог записать файл в репозиторий. Создаётся один раз:

1. https://github.com/settings/personal-access-tokens/new
2. **Token name**: например, «Смена пароля на сайте». **Expiration**: на ваш выбор.
3. **Repository access → Only select repositories →** `BuraqYetkazish`.
4. **Permissions → Repository permissions → Contents → Read and write**.
5. **Generate token** и скопируйте токен (`github_pat_…`) в поле на сайте.

Можно отметить «Запомнить токен на этом устройстве», тогда в следующий раз его не придётся
вставлять. Токен стирается с устройства при выходе из аккаунта.

### Пользователи и данные (из командной строки)

Нужен Node.js 18+. Для команд, которым нужен существующий ключ, укажите логин и пароль
любого текущего пользователя:

```bash
# добавить пользователя (пароль сгенерируется и напечатается один раз)
VAULT_LOGIN=buraq VAULT_PASSWORD='…' node tools/vault.mjs add-user manager

# свой пароль вместо сгенерированного
VAULT_LOGIN=buraq VAULT_PASSWORD='…' NEW_PASSWORD='…' node tools/vault.mjs add-user driver1

# вход «только просмотр» (роль viewer)
VAULT_LOGIN=buraq VAULT_PASSWORD='…' NEW_PASSWORD='…' node tools/vault.mjs add-user <логин> viewer

# сменить пароль: добавить того же пользователя с новым паролем
# (роль задаётся заново: без viewer вход получит все права)
VAULT_LOGIN=buraq VAULT_PASSWORD='старый' NEW_PASSWORD='новый' node tools/vault.mjs add-user buraq

# удалить пользователя
node tools/vault.mjs remove-user manager

# секрет редактора для ИИ-импорта (печатается один раз; то же — кнопкой на сайте, см. «Импорт манифестов»)
VAULT_LOGIN=buraq VAULT_PASSWORD='…' node tools/vault.mjs set-editor

# заменить данные на новый Excel (формат как у исходного файла)
VAULT_LOGIN=buraq VAULT_PASSWORD='…' node tools/vault.mjs set-data Mijozlar_omborlari_ro_yxati.xlsx

# начать заново: новый ключ, новые данные, один пользователь
node tools/vault.mjs init Mijozlar_omborlari_ro_yxati.xlsx buraq
```

После изменения закоммитьте `data/vault.json`. Удаление пользователя закрывает ему вход,
но старые версии `vault.json` в истории git открываются прежним ключом. Чтобы полностью
отозвать доступ, сделайте `init` заново: будет новый ключ и новые пароли. После `init` общие
настройки сайта пустые, поэтому Google Таблицу нужно подключить снова.

### Вход «только просмотр»

У пользователя может быть роль `viewer` (`"role": "viewer"` у его записи в `vault.json`). Такой вход видит всё:
журнал, клиентов, карту, дашборд, планы, 3D, тарифы и проверку, может скачать Excel и обновить данные из таблицы.
Изменить ничего нельзя:
- кнопки правок, «Принять план», «Настройки» → «Связь» и смены пароля скрыты;
- поля тарифов и ячейки журнала не редактируются;
- в Google Таблицу и Excel ничего не пишется.

В шапке на широком экране (от 1441 px) — метка «Только просмотр», в «Аккаунте» — пояснение. Пароль такого входа меняет руководитель
(командой выше или «Сменить пароль» с логином и текущим паролем этого входа). Ограничение — на уровне сайта:
ключ данных у входа тот же, что у руководителя.

## Данные и синхронизация

Приложение хранит рабочую копию данных в браузере (localStorage). Главный источник данных —
**Google Таблица**, если она подключена. Без неё источник — встроенные данные из `data/vault.json`.

**Google Таблица — одна на весь сайт.**

- Подключается в полосе над журналом: «Google Таблица» → код Apps Script → ссылка `/exec`.
  Ссылка вместе с паролем скрипта сохраняется в общих настройках сайта (зашифрованный
  `vault.json`, коммит «Общие настройки сайта»). Для этого нужен GitHub-токен, тот же, что
  для смены пароля. После пересборки сайта (1–2 минуты) все устройства после входа сами
  работают с этой таблицей. Без токена таблица подключается только на этом устройстве.
- При первом подключении пустая таблица заполняется данными сайта. Если данные отличаются,
  сайт спрашивает: «Взять из таблицы» (сайт покажет таблицу) или «Записать сайт в таблицу»
  (таблица станет как сайт, лишние строки удалятся).
- Правки на сайте сразу уходят в таблицу. Очередь неотправленных правок хранится на устройстве:
  если нет связи или приложение закрыли, правки уйдут при следующем открытии или когда появится
  сеть. Новые строки из таблицы подтягиваются каждые 30 секунд и при возврате в приложение.
- **Скрипт не отвечает — сайт пишет почему.** Раньше при любом сбое было только «Failed to fetch». Теперь:
  - «Нет связи с Google — проверьте интернет» — нет сети на устройстве;
  - «Скрипт таблицы не отвечает: вместо данных Google показывает свою страницу» — ошибка в коде скрипта, нужны
    разрешения, вход или ссылка устарела. Кнопка «Открыть скрипт» открывает ссылку …/exec: что там написано и что
    делать — «Настройки» → «Связь» → «Сайт пишет «Скрипт таблицы не отвечает» — что делать». Сайт отличает это от «нет
    сети» пробным запросом без CORS: страница Google приходит, без сети — нет;
  - ошибка кода скрипта — её текст (скрипт с 23 ловит ошибки и отвечает JSON `code: script`); таблица занята другой
    записью дольше 25 с — «повторю через полминуты» (`code: busy`).
  Правки при этом ждут на устройстве и уходят сами, когда скрипт снова отвечает.
- **Правка, которую таблица не приняла, не держит остальные** (скрипт версии 24). Если на ячейке в таблице стоит проверка
  данных с «отклонять ввод» (например, выпадающий список телефонов, который предлагает сам Google) или защищённый
  диапазон, скрипт не записывает только эту правку: уже записанные ячейки её строки возвращаются к прежним, остальные
  правки порции записываются. Сайт убирает эту правку из очереди (на сайте становится как в таблице) и показывает в
  полосе, что не записалось и почему — пока не нажмут «Понятно». Правка клиента уходит с прежними значениями, и скрипт
  пишет только изменённые ячейки: смена района не переписывает телефоны. Со скриптом ниже 24 одна отклонённая ячейка
  останавливает всю очередь — сайт подсказывает убрать проверку данных (выделить столбец → Данные → Проверка данных →
  удалить правило или «Показывать предупреждение») и нажать «Отправить снова».
- **Выпадающие списки в таблице больше не останавливают запись** (скрипт версии 26). Google Таблицы сами предлагают
  превратить столбец с повторяющимися значениями (получатели, телефоны) в выпадающий список — «проверку данных» с
  правилом «отклонять ввод». Тогда новое имя или номер, которого нет в списке, таблица не принимала («В ячейке F89
  нарушены правила проверки данных…»), и правка застревала. Теперь, если таблица отклонила ячейку по такому правилу,
  скрипт переключает правила этого столбца (строки с 5-й) на «Показывать предупреждение» и записывает правку снова:
  список остаётся подсказкой, значение не из списка пишется (в углу ячейки — треугольник). Это делается один раз на
  столбец; сайт один раз сообщает, какой столбец переключён («Mijozlar F»). Защищённые диапазоны так не обходятся — такая
  правка по-прежнему показывается как «Не записалось».
- **Сайт сам не меняет в таблице то, что вы задали.** В таблицу уходят только ваши правки на сайте; сами — лишь
  пустые настройки (значение по умолчанию) и район клиента, если он пустой. Прежние одноразовые правила (Gazel 23 → 19 м³,
  список машин с Changan, «первая точка в базовой цене», вместимость, точка склада) срабатывали заново на каждом новом
  устройстве и после «Выйти» и возвращали в таблицу старые значения поверх ваших — с 28.09 их нет.
- **Граница кольцевой (ТКАД)** хранится в листе «Halqa zonasi», ячейки `B11:C220` (широта, долгота). Сайт
  записывает её в таблицу только после «Карта» → «Редактировать границу» → «Сохранить». На новом устройстве и
  после «Выйти» граница берётся из таблицы как есть; пока таблица не загрузилась — граница из вашего Excel. Если код скрипта
  старше сайта, сайт тоже не пишет свою границу в таблицу. (До 28.09 одноразовая замена границы на встроенную линию
  срабатывала заново при таком входе и затирала границу в таблице.)
  Вернуть прежнюю границу: таблица → Файл → История версий → версия до изменения → лист «Halqa zonasi» →
  выделить `B11:C220` → скопировать → вернуться к текущей версии → вставить в `B11` того же листа. Сайт подхватит
  её за 30 секунд. «Восстановить эту версию» не нажимайте: откатится вся таблица, вместе с журналом и отметками водителей.
- «Отключить таблицу» отключает её на всех устройствах (нужен GitHub-токен).
- **Пароль скрипта обязателен** (скрипт версии 19): свойство `TOKEN` в Apps Script (⚙ Настройки проекта → Свойства
  скрипта) и то же значение на сайте в «Настройки» → «Связь» → «Пароль скрипта». Без свойства сайт пишет «Задайте TOKEN
  в свойствах скрипта», с другим паролем — «Неверный пароль скрипта таблицы»; правки при этом ждут на устройстве.
- Если сайт пишет «Обновите код скрипта…», значит, код Apps Script в таблице старее сайта и часть
  настроек (например, «точек в базовой цене» у Labo и Kamaz) в таблицу не записывается.
  В окне «Настройки» → «Связь» → «Скопировать код» → вставьте в Apps Script → **Развернуть →
  Управление развертываниями** → ✎ → Версия: **новая** → Развернуть. Ссылка останется прежней.

**Excel-файл:** в Chrome и Edge на компьютере файл подключается для записи. На телефоне файл
можно только загрузить, а сохранять через «Скачать Excel».

## Импорт манифестов (без ИИ или через ИИ)

Манифест партии (Excel или PDF) превращается в черновик партии. Разобрать его можно двумя способами —
переключатель вверху страницы импорта («Журнал» → «Импорт манифеста»), выбор запоминается на устройстве. Пользоваться импортом может только руководитель.

- **Без ИИ — бесплатно** (по умолчанию, `js/import-local.js`). Ничего настраивать не нужно.
  - **Excel:** сайт находит строку заголовков по словам: маркировка (SHIPPING MARK, 唛头, MARK), места (CTN, 件数),
    м³ (T/CBM раньше CBM), кг (G.W. раньше KG; нетто N.W. не берётся). Строки ниже — до итога (TOTAL, 合计, ИТОГО).
    Подытоги (SUBTOTAL, 小计) пропускаются. Маркировка объединённой или пустой ячейки берётся из строки выше.
    Число объединённой ячейки считается один раз. Строка без чисел — не груз.
  - **PDF с текстом:** столбцы — по положению заголовков на странице. Если строка таблицы — один кусок текста,
    маркировка берётся из начала строки, а числа из конца — по порядку столбцов.
    «1,320» у мест и кг — это тысячи, у м³ «1,234» — десятичная запятая.
  - **Скан** (страница-картинка) без ИИ не прочитать: сайт так и напишет.
  - Незнакомые маркировки сопоставляете вы, выбрав клиента. Маркировка запоминается в карточке клиента,
    и в следующий раз клиент узнаётся сам.
- **Через ИИ** — Claude через скрипт Google Таблицы: любой формат, в том числе сканы, и предложения клиентов
  для незнакомых маркировок. Платно, по счёту Claude API: центы за Excel-манифест, PDF дороже. Ключ API хранится
  только в скрипте, на сайт он не попадает. Настройка — ниже.

Дальше оба способа одинаковы: черновик, проверки кодом, подтверждение.

### Настройка ИИ (один раз, только для «Через ИИ»)

1. **Ключ Claude API.** [Claude Console](https://platform.claude.com) → [Settings → API keys](https://platform.claude.com/settings/keys) →
   **Create key**. Ключ начинается с `sk-ant-` и показывается один раз — скопируйте его. На счёте в Console должны быть
   деньги: если их нет, сайт так и напишет.
2. **Код скрипта версии 8.** На сайте: полоса над журналом → «Настройки» → «Связь» → «Скопировать код» → в Google Таблице
   **Расширения → Apps Script** → заменить весь код → Сохранить → **Развернуть → Управление развертываниями** → ✎ →
   Версия: **новая** → Развернуть. Ссылка остаётся прежней. С версии 19 скрипт без пароля закрыт: **до** обновления кода
   задайте свойства `TOKEN` и `EDITOR_TOKEN` (шаг 3), иначе новый код не пустит сайт.
3. **Свойства скрипта.** В Apps Script **этой таблицы** (Расширения → Apps Script): ⚙ **Настройки проекта → Свойства скрипта → Добавить свойство**,
   затем обязательно **«Сохранить свойства скрипта»** — без этого скрипт свойств не видит:

   | Свойство | Значение |
   | --- | --- |
   | `ANTHROPIC_API_KEY` | ключ из шага 1 |
   | `TOKEN` | **обязательно** (с версии 19): пароль скрипта — тот же, что на сайте в «Настройки» → «Связь» → «Пароль скрипта». Без него скрипт никого не пускает |
   | `EDITOR_TOKEN` | **обязательно** (с версии 19): секрет редактора: «Настройки» → «Связь» → «ИИ-импорт манифестов» → «Показать секрет» → «Скопировать». Без него ИИ-импорт и бот с сайта не работают. Не делайте его таким же, как `TOKEN` |
   | `AI_MODEL` | необязательно; по умолчанию `claude-sonnet-5`. Для сканов плохого качества можно `claude-opus-5-5` |

4. **Проверка.** «Настройки» → «Связь» → «ИИ-импорт манифестов» → **«Проверить ИИ»**: сайт покажет модель и время ответа.
   Если скрипт пишет, что ключа нет, — в ошибке перечислены свойства, которые он видит (только имена).
   Пустой список значит, что свойства не сохранены или добавлены в другой проект Apps Script. Регистр и пробелы в имени
   скрипт прощает, ключ `sk-ant-…` под другим именем тоже находит.
   Если сайт пишет «нет разрешения на вызов функции UrlFetchApp.fetch» (`script.external_request`), значит, владелец таблицы
   ещё не разрешил скрипту внешние запросы. В Apps Script выберите вверху функцию **`authorize`** (в старом коде — любую,
   например `doGet`) → **▶ Выполнить** → «Проверить разрешения» → свой аккаунт → «Дополнительные настройки» →
   «Перейти к проекту». На экране разрешений у каждого пункта своя галочка: отметьте **все** («Выбрать все»),
   иначе внешние запросы так и останутся запрещены. Запускать нужно под тем аккаунтом Google, от имени которого развёрнуто
   веб-приложение («Развернуть → Управление развертываниями» → «Выполнять как»). Это делается один раз. Потом снова «Проверить ИИ».

**Секрет редактора** — второй пароль, только для ИИ: скрипт не вызывает Claude без него. Сайт хранит секрет в `vault.json`
в настройках руководителя, зашифрованных отдельным ключом руководителя (у входа «только просмотр» этого ключа нет).
На устройстве, где вход был выполнен раньше, секрет открывается паролем входа («Открыть секрет»). «Новый секрет редактора»
создаёт новый (нужны пароль входа и GitHub-токен) — его нужно снова вписать в `EDITOR_TOKEN`. Без `EDITOR_TOKEN`
скрипт версии 19 отказывает ИИ и боту с сайта («Задайте EDITOR_TOKEN в свойствах скрипта…»); до версии 19 ИИ был доступен
по обычному паролю таблицы, в том числе входу «только просмотр».

**Модель и ответ по схеме.** Скрипт просит у Claude JSON строго по схеме: инструмент со `strict: true` и `tool_choice`
на этот инструмент. Claude Opus 5.5 и Fable 5.1 не принимают принудительный `tool_choice` (ошибка 400) — для них скрипт
передаёт ту же схему через `output_config.format` (structured outputs). Модель меняется свойством `AI_MODEL` без правки кода.

**Лимиты.** Файл — до 10 МБ, PDF — до 30 страниц (запрос к Claude — до 32 МБ, к Apps Script — до 50 МБ, выполнение скрипта —
до 6 минут). Один запрос Apps Script к внешнему API ждёт около минуты, поэтому большие документы разбираются частями.

**«ИИ-журнал».** Каждый вызов — строка в листе «ИИ-журнал» Google Таблицы (скрипт создаёт его сам): время, пользователь,
файл, черновик, действие, модель, часть, токены на входе / из кэша / на выходе, время ответа, итог. Подтверждённые импорты
(дата, маршрут, итоги) сайт берёт оттуда же, чтобы замечать повторный импорт той же партии.

**Маркировки клиента** (как клиент подписан в манифестах: `CBETKO`, `ECLIPSE`…) — поле «Маркировки в манифестах»
в карточке клиента, столбец Y «Markirovkalar» листа «Mijozlar». По ним импорт узнаёт клиента без ИИ.
Пределы плотности груза для предупреждений — «Настройки» → «Тарифы и планы» → «Импорт манифестов» (строки 71–72 листа «Sozlamalar»,
по умолчанию 40 и 800 кг/м³).

### Как пользоваться

1. **Загрузка.** «Журнал» → **«Импорт манифеста»** (кнопку видит только руководитель) → выбрать способ («Без ИИ» или «Через ИИ») →
   перетащить файл или «Загрузить манифест». Принимаются `.xlsx`, старый `.xls` (Excel 97–2003) и PDF.
   Через ИИ: Excel сайт читает сам и отправляет ИИ текстом (ячейки с адресами), PDF отправляет целиком. Большой документ
   уходит частями: ~70 строк Excel или 5 страниц PDF.
2. **Черновик.** Разбор сохраняется черновиком **на этом устройстве** (IndexedDB браузера), переживает перезагрузку.
   До подтверждения в журнал, базу клиентов и Google Таблицу не пишется ничего, кроме строк «ИИ-журнала».
   При выходе из аккаунта черновики удаляются вместе с остальными данными устройства.
3. **Экран проверки.**
   - Слева — документ, справа — строки черновика. Клик по строке подсвечивает её ячейки в Excel или строку на странице PDF.
     На телефоне и планшете документ и строки переключаются кнопками «Строки и клиенты» / «Документ».
   - Все поля правятся: дата партии, консолидатор, маркировка, места, м³, кг. Строки можно добавить и удалить.
   - Итоги, списки и планы A/B/C считает код (тот же `buildPlans`, что во вкладке «Планы»), а не ИИ.
     Из сводки ИИ на экран попадают только слова. Цифры в ней подставляет код.
4. **Проверки кодом.** Цифрам ИИ сайт не доверяет.
   - **Блокирующие** — пока они есть, кнопка «Подтвердить» не работает:
     - число или маркировка не совпадает с ячейкой документа;
     - строка документа пропущена или взята дважды;
     - сумма строк не сходится с итогом TOTAL. Допуск: места — точно, м³ — max(0,01; 0,1 %), кг — max(0,5; 0,1 %).
       Если итог неверен в самом документе, его можно «принять как есть»;
     - у маркировки нет решения по клиенту;
     - нет даты партии.
   - **Предупреждения** — видны у строк, но подтвердить не мешают:
     - число не распознано или не больше нуля;
     - плотность вне пределов из «Тарифов»;
     - в PDF число не найдено в тексте страницы, или страница — скан;
     - в документе нет итога;
     - похоже на повторный импорт: та же дата и те же итоги в журнале, в «ИИ-журнале» или в другом черновике;
       или в журнале за эту дату у большинства клиентов манифеста уже те же цифры — тогда сайт называет и тех,
       у кого цифры расходятся (так видна ошибка в уже внесённой партии);
     - «Исправлено вами» — вы поменяли число поверх документа.
   - **Списки:**
     - мелкие маркировки — меньше порога «Не платим за доставку» из «Тарифов»;
     - неизвестные маркировки и BL-00 (владелец неизвестен);
     - тяжёлые — плотность выше предела.
5. **Маркировки и клиенты.** Сначала маркировку узнаёт код: по коду `BL-146` / `BL146`, по маркировкам клиента и по бренду
   (если в карточке несколько брендов через запятую — по любому из них).
   Латиница, похожая на кириллицу, тоже сравнивается: `CBETKO` = «СВЕТКО». Остальные маркировки ИИ сопоставляет со справочником.
   ИИ получает только id, имя и маркировки клиентов, без адресов и телефонов. Он предлагает клиента с уверенностью и причиной,
   а решение принимаете вы: «Принять» или «Принять все предложения ИИ», другой клиент из списка или «без клиента».
   Если стоит галочка «Запомнить маркировку у клиента», при подтверждении маркировка допишется в карточку клиента,
   и в следующий раз клиент узнается без ИИ.
6. **Подтверждение.** «Подтвердить и создать партию» создаёт отгрузки тем же путём, что ручной ввод в журнале:
   - одна отгрузка на клиента: строки с его маркировками складываются;
   - машина «Belgilanmagan», статус «Rejada»;
   - в примечании — консолидатор и маркировки.

   Черновик получает статус «Подтверждён» и кнопку «Открыть журнал». В «ИИ-журнал» пишется строка с итогами.
   **«Отклонить черновик»** — партия не создаётся, причину можно указать.
7. **Статистика** над списком черновиков: сколько ждут проверки, подтверждено, отклонено, сколько правок вручную на манифест
   (доля исправленных полей и решений ИИ) — в целом и по моделям. По ней видно, можно ли сменить модель на более дешёвую.

**Реальные манифесты в репозиторий не кладите** — он публичный. Тесты импорта (`tests/import-*.test.mjs`) используют
обезличенный манифест `tests/fixtures/manifest.mjs` и поддельный ответ ИИ `tests/fake-ai.mjs`.

## Телеграм-бот для водителей

Бот работает внутри скрипта Google Таблицы (версия 34, код — `tools/gs/Code.gs` + `tools/gs/Bot.gs`, собирается
`node tools/build-gs.mjs`): бесплатно, отдельный сервер не нужен. Данные — та же таблица, что у сайта.

### Настройка (один раз)

1. **Бот.** В Telegram у [@BotFather](https://t.me/BotFather): `/newbot` → имя и адрес бота → **токен**. Там же по желанию:
   `/setuserpic` (логотип), `/setdescription`, `/setabouttext`. Команды вручную не нужны — бот задаёт их сам.
2. **Токен — в свойства скрипта.** Apps Script → ⚙ Настройки проекта → Свойства скрипта → «Изменить свойства скрипта» →
   «Добавить свойство»: `TG_TOKEN` = токен → **«Сохранить свойства скрипта»**. Токен не попадает ни на сайт, ни в репозиторий.
3. **Код скрипта версии 34.** Сначала в свойства скрипта — `TOKEN` = пароль скрипта (тот же, что в «Настройки» → «Связь» → «Пароль скрипта») и `EDITOR_TOKEN` = секрет редактора: без них код 19 не пустит сайт. «Настройки» → «Связь» → «Скопировать код» → заменить код в Apps Script → Сохранить → Развернуть →
   Управление развертываниями → ✎ → Версия: новая → Развернуть. Затем в Apps Script выбрать функцию **`authorize`** →
   ▶ Выполнить → отметить **все** галочки: добавятся доступ к Google Диску (фото) и внешние запросы (Telegram).
4. **Подключить.** На сайте: «Настройки» → «Связь» → «Телеграм-бот для водителей» → **«Подключить бота»**. Скрипт проверит токен,
   отдаст Telegram ссылку веб-приложения с секретом (`TG_SECRET`) и задаст меню команд на узбекском и русском.
   Там же ставятся два триггера: итог дня в 20:00 и `tgTick` раз в 5 минут (план утром, «Жду клиента», напоминания), а скрипт запоминает
   адрес сайта (`TG_SITE`) и ссылку веб-приложения (`TG_URL`) — по ним кнопка «📷 Сфотографировать» открывает камеру.
   После обновления кода нажмите «Переподключить бота» один раз.
5. **Группа отчётов.** Группа в Telegram, в ней бот и руководители (администраторы группы подтверждают водителей).
   Отправить в группе команду `/ulash <код>` — код показан на сайте.

### Как работает

- **Регистрация** (один раз, скрипт версии 31 — водитель на своей машине): `/start` → язык (O‘zbekcha / Русский) →
  имя → **телефон** (кнопкой «📞 Отправить мой номер» — только свой контакт, или текстом; 9 цифр — с +998) →
  **вид машины** кнопками (Gazel, Labo, Changan, Kamaz) → **госномер** → **марка и модель** → **кузов** внутри: длина,
  ширина, высота («4.2 2.1 2.2», «4,2x2,1x2,2» или в сантиметрах «420 210 220»; объём бот считает сам) →
  **грузоподъёмность** («1500», «1,5 т») → «Проверьте: …» → «Отправить». Заявка с машиной приходит в группу с кнопками
  «Разрешить / Отклонить»; нажать может только администратор группы. Разрешить или отключить водителя можно и на сайте.
  Пока доступа нет, бот ничего не показывает: в задании адреса и телефоны клиентов.
- **«Разрешить» — машина в автопарк** (версия 31). В группе: машина водителя записывается в автопарк сама — в машину
  того же вида с тем же госномером, иначе в свободную машину вида без госномера и водителя (не в ремонте), иначе
  новой «Вид-N» в первую пустую строку Sozlamalar C24:C39 (число машин вида в настройках растёт). Пишутся госномер
  (D), марка (F), объём (H), грузоподъёмность (I) и кузов (K:M); в группе под заявкой — «🚚 В автопарке: Gazel-1»
  («(новая)» — если машина добавлена).
  Нет места или E23:J23 заняты — доступ всё равно открывается, а в группе «⚠️ Машина не записана: …» — назначьте
  машину на сайте. На сайте — «Проверить и разрешить» (см. «Вкладка «Водители»»).
- **Задание.** На сайте во вкладке «Водители» руководитель выбирает партию (дату отгрузок) и нажимает «🚚 Отправить груз водителям»
  или «Отправить» в строке водителя: водитель получает задание — партия, число точек и рейсов, без списка (скрипт 20). Адрес, телефон
  и метку следующей точки он видит только после фото (доставки или места) и геолокации предыдущей. Партия везётся, даже если её дата не сегодня.
  Задание действует 3 дня; без задания бот берёт сегодняшнюю партию.
- **План дня утром — сам** (версия 14). В 08:30 по Ташкенту (время — на сайте: «Настройки» → «Водители и автопарк» → «Бот и диспетчер» →
  «План водителям утром», 07:00–10:00 или «Выкл»; свойство `TG_MORNING`) бот отправляет задание на сегодня каждому
  водителю, у машины которого в журнале есть сегодняшние точки. Кто уже работает или уже получил эту партию с сайта —
  не получает её второй раз. В группу — одно сообщение: «🌅 План на дд.мм отправлен водителям» (машина, водитель,
  точек), «Не отправлено: … — нет водителя в боте» и «⚠️ Без машины: N (BL…)» — отгрузки, которым не назначили машину.
  Если плана на сегодня нет (выходной), бот молчит. Отправка — один раз в день, в течение 3 часов после заданного
  времени (свойство `TG_MORNING_DAY` — день последней отправки).
- **Рабочий день.** «Начать работу» → геолокация → первая точка. Точки — строки журнала этой партии с машиной водителя
  (после «Принять план»); части одной отгрузки и строки одного клиента в рейсе — одна точка. Следующая точка — ближайшая
  к месту последней отметки (как в плане: от склада к ближайшей). Карточка: клиент, адрес, получатель и телефон,
  груз (места, м³, кг), примечание и метка на карте.
- **Карточка точки**: «✅ Доставлено», «❌ Не доставлено», «⏳ Жду клиента» и маршрут одной кнопкой — «🧭 Маршрут
  (Яндекс)» и «🧭 Google Maps» открывают навигацию до клиента.
- **Фото — только с камеры и обязательно** (и при «Не доставлено» — фото места). Кнопка «📷 Сфотографировать»
  открывает внутри Telegram страницу сайта `driver.html` (мини-приложение). Камера включается прямо на странице
  (живое изображение и круглая кнопка «снять») — выбора из галереи там нет. На снимок ставится штамп — BL, дата,
  время, координаты — и он уходит в скрипт. Скрипт пускает снимок только с подписью Telegram (`initData`, проверка
  токеном бота), пароль таблицы для этого не нужен. При открытии страница проверяет связь с ботом («связь с ботом ✓»
  или понятная ошибка). Если телефон не дал доступ к камере, страница объясняет, как его разрешить, и предлагает
  запасной путь — камеру телефона; тогда снимок старше 10 минут (по дате съёмки EXIF или дате файла) отклоняется
  как фото из галереи. Фото, присланные прямо в чат, бот не берёт. Место
  берётся со снимка — отдельный шаг «геолокация» не нужен. Если отметка дальше заданного расстояния от клиента
  (по умолчанию 1 км), в отчёте группы — «⚠️ Отметка в N км от точки клиента». Так точки закрываются по ходу дня,
  а не все вечером. Камеру можно выключить на сайте — тогда фото принимаются из чата, как раньше.
- **Шаг «фото» — коротко**: «📷 Сфотографируйте груз 👇» и одна кнопка камеры. На странице камеры — только BL,
  живое изображение и кнопка; после отправки — «✅ Готово» (закрывает точку, без возврата в чат) и «📷 Ещё фото».
  В чате снимок приходит с теми же кнопками прямо под ним.
- **«Доставлено»**: фото → «Готово». Статус отгрузки в журнале — «Yetkazildi», фото — на Google Диск (папка
  «BURAQ yetkazish» / дата), строка в листе «Yetkazish» (с минутами ожидания и расстоянием до клиента), отчёт с фото
  в группу.
- **«Не доставлено»**: причина кнопкой или текстом, фото места. Статус — «Qolib ketgan» («Осталось»), отчёт с
  причиной в группу.
- **«⏳ Жду клиента»** — таймер (по умолчанию 15 минут). Когда время вышло, бот спрашивает водителя «Клиент пришёл?»
  («Доставлено», «Не доставлено», «Ещё N мин»), а в группу пишет, сколько водитель ждёт, с номерами клиента.
  Сколько ждал — в отчёте о доставке и в журнале доставок на сайте.
- **«⚠️ Проблема»** — кнопка в меню (и `/muammo`): поломка, пробка, ДТП, ГАИ/штраф, топливо, другое → описание,
  фото (можно из галереи) → геолокация. Тревога с фото — в группу, запись — в лист «Muammolar», на сайте — в карточке
  машины и в «Ленте доставок».
- **«Не отвечает на телефон»**: бот не спешит закрывать точку. В группу сразу приходит тревога: какая машина,
  клиент, его номера и адрес — диспетчер звонит клиенту сам. У водителя — меню: «📞 Позвонить диспетчеру»
  (номер текстом и карточкой контакта — звонок одним нажатием), «☎️ Номера клиента», «✅ Клиент ответил —
  доставляю» (дальше как обычная доставка с фото), «❌ Всё равно не доставлено».
- **«📞 Диспетчер»** — кнопка в меню бота (и команда `/dispetcher`), если на сайте указан номер диспетчера:
  «Водители» → «Партия и водители» → «Диспетчер для водителей». Номер хранится в свойствах скрипта
  (`TG_DISP_PHONE`, `TG_DISP_NAME`).
- **Рейс 2**: когда точки рейса 1 закончились, бот просит вернуться на склад и начать рейс 2 кнопкой.
- **Напоминания** (версия 14, включены по умолчанию; выключаются на сайте — «Напоминания водителям», свойство
  `TG_REMIND`). Если водитель забыл нажать кнопку, бот напоминает ему тем же шагом и той же кнопкой, а если это не
  помогло — пишет в группу, чтобы водителю позвонили. Потом молчит, пока водитель что-нибудь не нажмёт.

  | Что случилось | Водителю | В группу |
  |---|---|---|
  | Начал шаг и бросил (фото, «Готово», причина, геолокация) | через 10 мин — «⏰» и тот же шаг с кнопкой | через 20 мин |
  | Карточка точки открыта, ничего не нажато | через время пути до клиента + 30 мин (не меньше 45): «⏰ BL…: доставили?» ✅ / ❌ / ⏳ | ещё через 30 мин, с последней отметкой |
  | «Клиент не отвечает» — решения нет | через 30 мин — снова то же меню | через 60 мин |
  | Рейс закончен, следующий не начат | через 60 мин — снова кнопка «▶️ Начать рейс» | — |
  | Все точки пройдены, день не закрыт | через 30 мин — «⏰ Работа закончена?» с кнопкой «🏁 Закончить работу» | — |
  | Есть задание, день не начат | через час после утренней отправки (09:30) — «⏰ Сегодня вас ждут точек: N» с кнопкой «🚚 Начать работу» | ещё через 30 мин: «… ещё не вышел на линию» |

  Напоминаний нет ночью (до 7:00 и после 22:00), во время «⏳ Жду клиента» (у него свой таймер) и час после
  «⚠️ Проблема». Время считает триггер `tgTick` (раз в 5 минут), поэтому напоминание может прийти на 5 минут позже.
- **«Закончить работу»**: геолокация, итог дня водителю и в группу; начало и конец дня — лист «Ish kuni».
- **Изменения на сайте.** Если отгрузки машины в отправленной партии поменяли (например, точку передали другой машине),
  водителю приходит «рейсы изменились» и новая точка, а тому, кто ещё не начал, — обновлённое задание.
- **Итог дня** — в группу каждый день в 20:00 (триггер ставится при «Подключить бота») или кнопкой на сайте.
- **Недоставленные — на завтра.** В 20:00, вместе с итогом дня, отгрузки «Qolib ketgan» из партий, которые сегодня
  развозили, переезжают на завтрашнюю дату: статус «Rejada», машина не назначена, в примечании «повторно: не
  доставлено дд.мм.гггг». Попытка с причиной остаётся в «Yetkazish». Выключается на сайте; любую партию можно
  перенести и вручную — «Водители» → «↪️ Перенести».
- **Уведомления клиентам** (на узбекском). В карточке клиента на сайте — ссылка `t.me/<бот>?start=<BL>`: клиент
  открывает её и делится номером телефона. Если номер есть в карточке (телефон 1, 2 или получателя) — подписка сразу,
  иначе заявку подтверждает администратор группы. Клиент получает: «сегодня доставим» (когда партию отправили
  водителю), «водитель в пути, будет примерно в …» (когда его точка стала текущей; время — по расстоянию,
  скорости и коэффициенту дороги из «Тарифов»), «водитель у вас, ответьте на звонок» (если не дозвонился),
  «доставлено» с фото или «не доставили, причина…» с номером диспетчера. `/stop` — отписаться. Подписки — лист
  «Obunalar». Кто подписан — в карточке клиента на сайте.
  Сайт отправляет в таблицу только изменённые поля (вместе с прежними значениями), поэтому статус, поставленный
  водителем, не перезапишется старым значением сайта.
- Листы бота: «Haydovchilar» (водители; последний столбец — состояние диалога, для скрипта), «Yetkazish», «Ish kuni».
  Telegram присылает сообщения на ссылку веб-приложения; скрипт отвечает через `HtmlService` (без переадресации 302)
  и пропускает повторы одного и того же обновления.

### Вкладка «Водители»

- **Отправить груз водителям.** Вверху — партия (дата) и большая красная кнопка «🚚 Отправить груз водителям»: задание
  уходит всем водителям, у машин которых есть точки в этой партии. Рядом — сколько точек и машин, у каких машин
  нет водителя в боте, сколько отгрузок без машины. Там же «Написать всем на линии», «Итог дня в группу» и перенос
  недоставленных на другую дату.
- **Отправить сразу после «Принять план».** Во вкладке «Планы» после «Принять план» сайт спрашивает «Отправить
  водителям сейчас?»: «Да, отправить» — машины из плана записываются в таблицу и задание уходит водителям; «Позже» —
  отправите здесь кнопкой. Вопрос появляется, только если бот подключён.
- **Новые водители** — плашкой, пока есть заявки. Заявка со своей машиной (скрипт 31): вид, госномер, марка, кузов,
  объём, грузоподъёмность и телефон; **«Проверить и разрешить»** — окно, где всё можно поправить и выбрать, куда
  в автопарке: «+ новая машина Gazel-N» или машина автопарка этого вида, кроме «в ремонте» (по умолчанию — с тем же
  госномером или свободная без госномера). «Разрешить» — машина записывается в автопарк, водитель получает доступ и эту машину,
  сайт сразу забирает новый автопарк. Заявка старым кодом (без машины) — как раньше: машина из списка, «Разрешить» /
  «Отклонить».
- **Кто на какой машине** (скрипт версии 23) — выбирает руководитель: в списке водителей в столбце «Машина» и в заявке
  перед «Разрешить». В выборе — машины автопарка (кроме «в ремонте» и служебных) с госномером и тем, кто на ней сейчас,
  и «— без машины». Одна машина — один водитель: если машина уже у другого водителя (или в чужой заявке), сайт
  спрашивает, и у того водителя машина снимается — он остаётся без машины, пока вы не назначите другую. Водителю бот
  пишет «🚚 Вам назначена машина: …» или «Машина … больше не за вами»; кто уже на линии, сразу получает точки новой
  машины (начатый шаг на старой машине сбрасывается, точка остаётся у старой машины). Без машины водитель не может
  начать работу и не получает задание («Отправить» — «нет машины»). Госномер водителя — из автопарка.
- **Список водителей**: машина и госномер (со скриптом 23 — выбор машины), что сейчас (на линии с …, текущая точка, закончил, задание отправлено),
  точки этой партии и сколько доставлено; кнопки «Отправить» (только этому водителю), «Позвонить» (если телефон
  вписан), «Написать», «Отключить». Отключённых можно снова «Разрешить». На телефоне список — карточками.
- **Карточка водителя** (скрипт версии 30): ✎ у имени — окно «Водитель»: имя и телефон (лист «Haydovchilar», столбец K
  «Telefon»; телефон виден в списке «📞 …» и кнопкой «Позвонить»), машина с кнопкой «Карточка машины ✎» (название,
  госномер, ремонт). ✎ у машины в списке — сразу карточка машины. **«Удалить водителя»** — строка водителя убирается из
  листа, бот пишет ему «нет доступа» и снимает клавиатуру; напишет боту снова — придёт новая заявка. «Отключить» —
  как раньше: водитель остаётся в списке «Отключены». Скрипт ниже 30 — сайт попросит обновить код.
- **Одна машина — у нескольких водителей** (например, заявку подтвердили в группе, старым кодом) — над списком красная
  плашка «⚠ Одна машина — у нескольких водителей: Gazel-1 — Ali, Vali»: бот даёт точки машины каждому, назначьте
  лишним другую машину.
- **Кто что везёт** — по каждой машине рейсы с загрузкой к вместимости, точки с итогом, фото и местом отметки,
  проблемы в пути; «Передать →» — точка уходит другой машине (в журнале меняются машина и рейс). Внизу — карта партии.
  Отгрузки без машины водитель не получит — сайт о них предупреждает.
- **Лента доставок** — отметки водителей за период с фото и местом, фильтры по машине и итогу, проблемы в пути, Excel.
- **Настройки** — не здесь, а в «Настройки» → «Водители и автопарк»:
  - **бот и диспетчер** (скрипт версии 12): имя и телефон диспетчера, сколько ждать клиента, с какого расстояния
    отмечать «далеко от клиента», фото только с камеры, перенос недоставленных на завтра; с версии 14 — время
    утренней отправки плана («Выкл», 07:00–10:00) и напоминания водителям;
  - **машины по видам**: сколько машин вида (и сколько из них в ремонте) и вместимость вида — те же настройки, что
    в «Тарифах и планах»;
  - **машины** — таблица с госномером (можно вписать прямо в строке), статусом, маркой и вместимостью; у каждой
    машины — **«Изменить»**, над таблицей — **«+ Добавить машину»**. В карточке машины:
    - вид (Gazel, Labo, Changan, Kamaz — только у новой) и **название**: начинается с вида (`Gazel-Ali`; «Ali» сайт
      дополнит до `Gazel-Ali`), по нему тариф. Переименование — одной правкой скрипта: список машин, журнал (все строки
      с этой машиной) и водители бота;
    - **госномер**;
    - **«В ремонте»** — машина не идёт в планы (машин вида для планов — «Машин в автопарке» минус те, что в ремонте) и
      бот не предлагает её водителю при регистрации; в журнале у неё пометка «в ремонте»;
    - **марка, год, примечание** — для справки;
    - **кузов внутри** (скрипт версии 31): длина × ширина × высота, м — все три или ни одного; пустой объём сайт
      посчитает из кузова. По кузову рисуется 3D во «Визуализации» (без него — типичные ширина и высота вида, длина из
      объёма). Водитель пишет кузов в боте при регистрации;
    - **свой объём и вес** — пусто: как у вида в «Тарифах и планах». Планы раздают рейсы по машинам поимённо: рейс
      достаётся машине, в которую помещается (сначала самая маленькая подходящая), а если рейсы под самую большую машину
      не нашли места — план пересчитывается по самой маленькой машине вида. В отчётах загрузка — по вместимости машины;
    - **«Удалить»** — любую машину; с точками в журнале на сегодня и дальше — сначала передать их другой машине;
      если машину выбрал водитель в боте, сайт предупредит.
  - Где хранится: список машин — Sozlamalar C24:C39 (не больше 16), госномер — D, карточка — E:J (E «Holati»:
    `ta’mirda`, F «Marka», G «Yili», H «Hajm, m³», I «Yuk, kg», J «Izoh»; заголовки — в строке 23), кузов — K:M
    («Uzunlik, m», «Kenglik, m», «Balandlik, m», скрипт 31; заняты чем-то своим — кузов не пишется). Госномер и карточка
    держатся за название: список поменялся — они переезжают вместе с названием. Если E23:J23 заняты чем-то своим, скрипт
    карточку не пишет и просит их освободить. Со скриптом ниже 21 в карточке открыт только госномер (и добавление,
    удаление машины).

- **Часовой пояс.** Если у Google Таблицы часовой пояс не Ташкент, вкладка «Водители» предупреждает и

  «Переподключить бота» (итог дня ставится заново).
- **Даты партий не сдвигаются** (скрипт версии 16). Раньше скрипт записывал дату партии как полночь по часовому поясу
  *скрипта* (Apps Script → ⚙ Настройки проекта), а таблица показывает её в своём поясе. Если у скрипта стоял,
  например, «Алматы» или «Екатеринбург», то в годы, когда смещение этих поясов отличалось от ташкентского (Алматы —

  сам ставит на полночь (свойство `SHIP_DATES_FIXED`), а сайт и бот читают дату партии с той же поправкой: время
  18:00 и позже — это полночь следующего дня из пояса восточнее (Алматы до 2024 года — 23:00, Китай — 21:00),
  раньше 18:00 — тот же день из пояса западнее (Москва — 02:00, Лос-Анджелес — 12:00–13:00).

  изменений; кнопки списка машин из старых сообщений бота ведут на шаг «вид машины».
- **Карточка водителя** (скрипт версии 30): действия бота `drvedit` (имя, телефон — Haydovchilar K) и `drvdel` (удалить
  строку водителя, ему — «нет доступа»); см. «Вкладка «Водители»».
- **Кто на какой машине** (скрипт версии 23): машину водителю назначает руководитель на сайте — действие бота `truck`
  (и `truck` в подтверждении заявки); см. «Вкладка «Водители»».
- **Откуда и куда** (скрипт версии 22): в «Задании» и в карточке каждой точки — «🏭 Откуда: склад отправки — адрес»
  и «📍 Куда: район, адрес клиента» (у клиента без адреса — «адрес не указан»). Склад — «Название» из «Тарифы и планы» →
  «Склад отправки», адрес — по его координатам (геокодер Google, на языке водителя; запоминается в свойстве скрипта
  `TG_DEPOT_ADDR`, пока координаты склада те же). Не удалось получить адрес — только название склада.
- **Карточка машины** (скрипт версии 21): «в ремонте», марка, год, свой объём и вес, примечание, переименование
  машины — «Настройки» → «Водители и автопарк». Машина в ремонте не идёт в планы и не достаётся новому водителю.
- **Следующая точка — только после фото** (скрипт версии 20). Фото обязательно и раньше: «Готово» без снимка бот не
  принимает, при «Не доставлено» — снимок места. Теперь и в задании нет списка всех точек (BL, бренды, районы): только
  партия, число точек и рейсов. Карточку и метку следующей точки водитель получает после фото и геолокации предыдущей.
- **Скрипт закрыт без пароля** (версия 19). `TOKEN` обязателен: без него на любой запрос ответ «Задайте TOKEN в свойствах
  скрипта», с чужим паролем — «Неверный пароль»; данные таблицы не отдаются. `EDITOR_TOKEN` обязателен для ИИ-импорта и
  бота с сайта. Обновления Telegram (ссылка с секретом бота) и фото с камеры водителя (подпись Telegram) проверяются, как
  раньше, своими подписями. Раскрытие коротких ссылок на карту ходит только на Google Карты (`google.*/maps`,
  `maps.google.*`, `maps.app.goo.gl`, `goo.gl`), Яндекс Карты (`yandex.*/maps`, `maps.yandex.*`) и 2ГИС (`2gis.*`,
  `go.2gis.com`) — и по исходной ссылке, и по каждой переадресации; на другой адрес скрипт не заходит.
- **Один план — одно сообщение** (скрипт версии 18). Раньше водитель мог получить один и тот же план 2–3 раза подряд:
  сайт пишет журнал в таблицу порциями (по 40 правок, при «Принять план» — несколькими запросами), и после каждой
  порции водитель, у которого задание уже было (например, утреннее), получал «Задание изменилось» со всем списком, а
  потом ещё и само задание. Теперь:
  - об изменениях — одно сообщение после последней порции; пока на сайте открыт вопрос «Отправить водителям сейчас?»
    (после «Принять план»), запись тихая: «Да» — водителю одно задание, «Позже» — одно «Задание изменилось»;
  - «Отправить груз водителям» (всем) не повторяет тот же план тому, кто его уже получил (в том числе утром) или уже
    везёт, — на сайте «Уже есть, повторно не отправлено»; повторить одному — «Отправить» в строке водителя;
  - кто уже везёт партию, не сбрасывается на начало: текущая точка и шаг (фото, ожидание) остаются;
  - «Новое задание», «Рейсы изменились» и «Кнопка устарела» приходят одним сообщением с карточкой точки;
  - действия сайта с ботом идут под той же блокировкой, что и кнопки водителей (две отправки одновременно не
    задваивают задание); если сайт не дописал порции, водитель узнает об изменении по таймеру через 2–7 минут.
- Вход «только просмотр» видит вкладку без кнопок. Со скриптом версии 9 заявки подтверждаются, но отправлять партии,
  писать водителям и хранить госномера можно только с версией 10, настройки бота и перенос — с версией 12,
  план утром и напоминания — с версией 14.

## Автопарк компании: файл сайта, карточки и фото

Машины компании записаны в репозитории — `data/fleet.json` (`vehicles`: `name` — название, начинается с вида: Gazel,
Labo, Changan, Kamaz; `plate` — госномер; `model`; `m3`; `kg`; кузов `l`, `w`, `h` в метрах (внутренние размеры);
`driver` — водитель по списку; `photos` — файлы в `img/fleet/`, JPEG до 1280 px). Фото и госномера в репозитории
открыты всем, у кого есть ссылка на сайт; данные журнала и клиентов — нет (они под паролем).

- **«Настройки» → «Водители и автопарк» → «Машины»** — карточки: фото (нажатие — просмотр, ‹ › листают, Esc
  закрывает), название и вид, госномер-табличка (поле правится как раньше), марка, полоса загрузки на партию,
  вместимость и полезный объём (с учётом «Полезный объём кузова, %»), кузов, водитель (из бота, иначе по списку файла),
  рейсы за период, «Фото» и «Изменить». Без фото — заглушка с видом машины. Машина файла узнаётся по госномеру, иначе
  по названию.
- **«Применить автопарк из файла»** — плашка появляется, когда таблица расходится с файлом (нет машин файла или есть
  лишние). Кнопка записывает в Google Таблицу список машин (Sozlamalar C24:C39 — лишние убираются, служебные строки
  «самовывоз» и «не назначена» остаются), госномера, карточки (объём, вес, кузов, марка) и число машин по видам — из
  файла; машина с тем же госномером под новым именем переименовывается в журнале и у водителей бота. Перед записью —
  подтверждение с перечнем. Новая (пустая) таблица получает машины файла вместо «Gazel-1…9».
- Чтобы добавить машину: фото → `img/fleet/`, запись → `data/fleet.json` (и в `sw.js`, чтобы фото были офлайн),
  затем на сайте — «Применить автопарк из файла». Или без файла — «+ Добавить машину» в карточках, как раньше.

## Клиент по ссылке на карту

В карточке клиента первое поле — «Ссылка на локацию». Вставьте ссылку из Яндекс Карт, Google Карт или 2ГИС (или
координаты «41.31, 69.27»), остальное заполнится само:

- **Координаты** берутся из самой ссылки сразу (`coordsFromLink` в `js/logi-engine.js`). Понимаются метка Google
  (`!3d…!4d…`), `?q=`, `@…`, у Яндекса — `pt`, «Что здесь», поиск по координатам, маршрут, у 2ГИС — объект.
  Перепутанные широта и долгота встают на место по границам Узбекистана.
- **Короткие ссылки** («Поделиться» в телефоне: `maps.app.goo.gl/…`, `yandex.uz/maps/-/…`) раскрывает скрипт
  Google Таблицы (версия 7): он проходит по перенаправлениям, а если координат нет и в полной ссылке, берёт их
  со страницы карты. Без таблицы или со старым скриптом сайт попросит обновить код или вставить полную ссылку.
- **Адрес** (если поле пустое) — геокодер Google Карт через тот же скрипт, на узбекском; без скрипта —
  OpenStreetMap. **Район** (если «Авто») — по адресу, иначе по соседним клиентам. **Зона кольцевой** — по координатам.
- Ссылку можно вставить и в поле широты — сайт поймёт.
- В «Настройки» → «Проверка данных» у «Клиенты без координат» кнопка «Найти по ссылкам» заполняет координаты всем, у кого
  ссылка есть, а координат нет.
- Там же «Необычная дата партии»: партии с датой больше года назад или дальше трёх месяцев вперёд (обычно опечатка
  в годе, например 2006 вместо 2026). Нажмите на партию — откроется карточка, где дату можно исправить.
- Склад отправки — так же: «Настройки» → «Тарифы и планы» → «Склад отправки» → «Ссылка на склад». Сейчас склад стоит по ссылке владельца:
  41.383782, 69.233623 (раньше в Excel была примерная точка — сайт заменил её сам, и в Google Таблице тоже;
  координаты склада, которые уже меняли вручную, не трогаются).

При обновлении скрипта до версии 7 Google попросит разрешить скрипту «подключаться к внешним сервисам» —
это нужно, чтобы открывать короткие ссылки.

## Журнал: группы по рейсам и две партии

Строки партии в журнале собраны в группы — переключатель «Группировка» над таблицей (выбор запоминается на устройстве):

- **По машинам** (по умолчанию). Группа — рейс: «GAZEL-1 · РЕЙС 1», рядом итог рейса — точки, м³, кг, цена рейса и
  «компания · с клиентов». Строки внутри — в порядке объезда. Ниже рейсов — «Без машины», «🙋 Самовывоз» (синим) и
  «Отменено». Машина без номера рейса — своя группа «… · без номера рейса».
- **По районам** — группа на район с числом точек, объёмом и весом.
- **Без групп** — сплошной список, как раньше.

Столбцы: Клиент, Район, Получатель (с телефоном), **Груз** (м³, под ним кг и мест), Машина, Рейс, Статус,
«Зона · оплата», доля цены. Шрифт строк одного размера, второстепенное — мелкой строкой ниже. Столбец «Дата» виден
только для «Все партии» и двух партий.

**«+ вторая партия»** — рядом с выбором партии в журнале, на «Карте», во «Водителях» и в «Отчёты → Партия на день»:

- **Журнал** — строки обеих партий; рейсы подписаны датой («GAZEL-1 · РЕЙС 1 · 05.10»), доля и цена рейса — по
  каждой партии отдельно; «📤 В группу» отправляет обе партии одной сводкой.
- **Карта** — точки и маршруты обеих партий.
- **Водители** — одно задание на обе партии («Партия 05.10.2026 + 06.10.2026: …»), как «Да, отправить» после плана
  на две партии (скрипт таблицы версии 28).
- **Партия на день** — «Отчёт по двум партиям»: рейсы обеих партий с датой, итоги вместе; печать и Excel — тоже.

## Куда везти: точки клиента и «Какая локация на эту партию?»

Клиент может попросить привезти груз не на свой адрес, а на другой склад. Его точки хранятся в анкете клиента, а точку
на каждую партию выбирают в журнале (скрипт таблицы версии 27).

- **Точки клиента — в анкете.** «Клиенты» → «Изменить» → «Точки доставки»: вставьте ссылку из Яндекс Карт, Google Карт,
  2ГИС (короткую тоже) или координаты «41.311, 69.279», по желанию название → «Добавить»; ✕ — убрать. Новая точка
  встаёт сверху. Основной адрес клиента (ссылка, широта, долгота) — как раньше. Доп. склады сайт больше не создаёт;
  уже записанные в «Qoshimcha omborlar» тоже есть в списке («Склад: …»).
- **Имя точки — адрес с карты.** Вставили ссылку или координаты — сайт сам находит адрес точки (через скрипт таблицы,
  Google; без таблицы — OpenStreetMap) и показывает его: «✓ Точка: … Адрес: Chilonzor, Bunyodkor 1». Без названия точка
  так и называется — по адресу; со своим названием — «Склад — Chilonzor, Bunyodkor 1». Адрес не нашёлся — «Точка 1», как
  раньше. Старые точки «Точка 1» / «Nuqta 1» сайт при входе руководителя один раз переименовывает адресом — в анкете и
  в строках, которые ещё везём (доставленные не трогает); адрес не нашёлся — точка остаётся как была.
- **Название точки можно поправить** в анкете («Точки доставки» — название в поле): после «Сохранить» новое имя видно
  в «Куда везти», журнале, планах и у водителя — в строках, которые ещё везём, оно меняется тоже.
- **«Какая локация на эту партию?»** Окно выскакивает само, когда в журнале выбирают партию (и после входа — для
  открытой партии), если у кого-то в ней точка ещё не выбрана. В окне все клиенты партии (кого ещё везём): у каждого
  список — «Адрес клиента», точки из анкеты, склады и «Новая точка… (ссылка или координаты)». Новая точка сохраняется в
  анкету клиента. «Сохранить» — точка у всех строк клиента в партии; «Позже» — окно закроется и выскочит при следующем
  выборе этой партии. Изменить потом — кнопка «📍 Локации партии» в журнале (красная точка — не всё выбрано) или список
  «Куда везти» в строке (нажмите на машину, рейс или статус) и в окне «Изменить» отгрузки.
- **По умолчанию** в окне — новая точка из анкеты, куда этого клиента ещё не возили; иначе — куда возили в последний раз;
  иначе — адрес клиента. Если у клиента одна точка — она и стоит.
- **Одна точка на все строки клиента в партии:** части одного груза едут в одно место. Новая строка клиента в партии
  сразу получает её точку.
- Своя точка видна в журнале под клиентом («📍 Склад Сергели»), кнопка «Карта» строки ведёт к ней. Планы (порядок точек,
  зона кольцевой и цена рейса), маршрут в Яндекс Картах, карта партии, отчёты, «Водители» и бот — тоже по ней.
  У водителя в карточке точки — «📍 Куда: …», навигатор и «ближайшая точка» — по ней же.
- **Где хранится:**
  - точки клиента — лист «Mijozlar», столбец **Z** «Lokatsiyalar», по строке на точку «Название · широта, долгота»
    (новые сверху);
  - точка партии — лист «Yuborishlar», столбец **V** «Yetkazish joyi»: «Название · широта, долгота» или «Mijoz manzili»
    (выбран адрес клиента). Пусто — точку ещё не выбирали: везут на адрес клиента, а сайт спросит.
  - Подписи Z4 и V4 скрипт ставит сам. Если столбец уже занят своим (другая подпись), скрипт туда не пишет и сайт
    покажет почему. В таблице можно вписать в V и вручную: «название · широта, долгота», только координаты или
    название точки клиента. В Excel-файле — те же столбцы (окно — кнопкой и при выборе партии).
- Со скриптом ниже 27 выбора нет (плашка «Обновите код до 27»), везут на адрес клиента.
- **Самовывоз.** В «Куда везти» (в строке, в окне «Изменить» и в окне партии) последний пункт перед «Новая точка…» —
  «🙋 Клиент заберёт сам»: клиент приезжает за грузом сам, он просто получатель. У всех строк клиента в партии, которые
  ещё везём, машина становится «Клиент заберёт» (в таблице — «Mijoz ozi oladi»), номер рейса стирается. Такие строки не
  идут в планы, на карту партии, водителям и в бот; окно «Какая локация на эту партию?» про них не спрашивает. В журнале
  строка синяя, под клиентом — «🙋 Клиент заберёт сам» (так же — строки со статусом «Клиент забрал сам»). Выбрать снова
  адрес или точку — самовывоз снимется, машина — «Не назначена». В «📤 В группу» такие клиенты — одной строкой в сводке
  («🙋 заберут сами: …»), без карточек. Можно и по-старому: «Машина» → «Клиент заберёт».
- **Без координат.** Строка, у которой нет точки на карте (у клиента нет координат и своя точка не выбрана), — красная,
  вместо «Карта» — кнопка «📍 Указать точку»: открывается анкета клиента, куда вставляется ссылка с карты (координаты,
  район и зона заполнятся сами). Отменённые и самовывоз не подсвечиваются.

## Партия в группу: «📤 В группу»

В журнале рядом с выбором партии — кнопка «📤 В группу» (и в «Планах» — для выбранной партии или пары партий).
Она отправляет партию в группу отчётов Telegram так же, как бот присылает водителю, — всё по отдельности (скрипт
таблицы версии 29):

- первое сообщение — сводка: партия, число клиентов, общий груз (м³ · кг · мест) и сколько клиентов со своей точкой, по
  адресу клиента и без координат;
- потом каждый клиент — отдельным сообщением-карточкой: «📦 Партия 06.10.2026 · 3 из 12», BL и клиент, «📍 Куда» (своя
  точка или адрес клиента), получатель с телефоном, груз (строки клиента в партии вместе); под карточкой — кнопки
  «🧭 Яндекс» и «🗺 Google» (маршрут до точки). Без координат — «Точки на карте нет — по адресу» и без кнопок.
- Отменённые отгрузки не попадают. Текст — по-русски, как остальные отчёты группы.
- Telegram пускает в группу не больше 20 сообщений в минуту: партия больше 18 клиентов уходит с паузами (~3 с на
  сообщение, сайт пишет, сколько примерно ждать). За раз — до 100 клиентов. Пока идёт отправка, сайт работает как обычно.
- Нужны подключённый бот и привязанная группа («Настройки» → «Связь»); иначе сайт скажет, что сделать.

## Планы маршрутов

Вкладка «Планы A/B/C» раскладывает отгрузки партии по рейсам (`buildPlans` в `js/logi-engine.js`): планы A, B, X
(пробный, по районам) и свёрнутый C.

- **Кто платит за доставку** (`costSplit` в `js/logi-engine.js`). Рейсы и груз не меняются, делится только цена рейса:

    отдельными рейсами, полоса об этом скажет.
  Правка для руководителя; вход «только просмотр» видит план и карту без правки.
- **Принять план.** Карточка под планами: «Принять план A» (B, C — выбранного плана) записывает в журнал
  машину и номер рейса каждой отгрузке партии. Номер рейса — у машины за день: «Gazel-3 · рейс 2» → машина
  Gazel-3, рейс № 2. Перед записью сайт показывает, что изменится.
  - Большая отгрузка, разделённая на рейсы, становится несколькими строками журнала: первая часть остаётся
    в исходной строке, остальные добавляются. В примечании — «часть 1/2», «часть 2/2». Объём, вес и места
    частей в сумме равны исходным.
  - Отгрузки без координат и статусы не меняются.
  - Новые машины (например, Gazel-7) добавляются в список машин журнала и таблицы.
  - Сразу после записи — «Открыть журнал →» и «Отменить»: отмена возвращает прежние машины и рейсы
    и убирает добавленные части (их узнаёт по содержимому, даже после синхронизации с таблицей).
  - Отметка «✓ План записан» держится, пока журнал партии совпадает с планом.

  Сумма рейсов в журнале совпадает с планом: точки рейса считаются в порядке объезда, как в плане
  (ближайшая к складу, потом ближайшая к ней), поэтому в базовую цену входит та же первая точка.

Листы «Reja A/B/C» в Excel считаются своими формулами и этих правил не знают. Для решений используйте вкладку «Планы» на сайте.

## Отчёты

Вкладка «Отчёты» (`reportBatch`, `reportView` в `index.html`) открывается на **дашборде**; подвкладки сверху —
Дашборд · Партия на день · Расходы · Автопарк · Водители · ИИ-отчёт. Отчёты:

- **Партия на день.** Рейсы по машинам и точки в порядке объезда: клиент, адрес, получатель и телефон,
  объём, вес, места, прибытие, зона, доля цены. Итоги: отгрузки, объём, рейсы, пробег, стоимость
  и расходы: компания платит / с клиентов (< 1 м³, за кольцом). Внизу — отгрузки без рейса. «+ вторая партия» —
  отчёт по двум партиям (см. «Журнал: группы по рейсам и две партии»).
- **Расходы** (за период). Итоги и таблица по партиям (стоимость, компания платит, с клиентов, сум за м³),
  стоимость по машинам и по районам.
- **Автопарк** (автопарк и экономия). По видам машин: машин в парке, рейсы, самый загруженный день, сколько машин
  нужно в этот день и сколько рейсов можно в день (машин × «Рейсов на машину в день»), средняя загрузка,
  рейсы загруженные меньше чем наполовину. Сравнение планов A, B, C и журнала по партиям и выводы.

Откуда берутся рейсы и стоимость:
- если у партии в журнале есть рейсы (машина и номер рейса, например после «Принять план») — из журнала;
- иначе — из плана A, с пометкой «по плану A».

Время рейсов по журналу:
- первый рейс машины выезжает в начале дня;
- следующий рейс этой машины — после возвращения предыдущего.

Особые случаи:
- Рейсы без тарифа (сейчас Kamaz) в сумму не входят и помечаются «+».
- Партии, где у отгрузок пустые CBM и KG, входят в стоимость, но не входят в загрузку и цену за м³. Отчёт об этом предупреждает.
- «Самый дешёвый» план не указывается, если у другого плана есть рейсы без тарифа и уже известная сумма меньше.

Период для расходов и автопарка:
- месяц (по умолчанию — месяц последней партии);
- всё время;
- свой период: с … по ….

Выгрузка:
- **Скачать Excel** — выбранный отчёт отдельным файлом: лист «Итоги» и таблицы отчёта. Имена файлов латиницей:
  `BURAQ_partiya_2026-08-27.xlsx`, `BURAQ_xarajatlar_2026-08.xlsx`, `BURAQ_avtopark_2026-08.xlsx`.
- **Печать / PDF** — печатается только отчёт, на A4:
  - сверху логотип BURAQ, название отчёта и время формирования;
  - меню и кнопки скрыты;
  - длинные таблицы переходят на следующую страницу по строкам, заголовок таблицы повторяется;
  - чтобы получить PDF, в окне печати выберите «Сохранить как PDF».

Отчёты видит и вход «только просмотр».

### ИИ-отчёт: проблемы и предложения

«Отчёты» → «ИИ-отчёт» (`aiRepFacts`, `aiRepMake`, `aiRepView` в `index.html`). ИИ читает сводку за период и пишет итог,
проблемы и предложения по трём темам: доставки и водители, расходы и машины, качество данных.

1. Выберите период: **одна партия** (по умолчанию — последняя прошедшая), **7 дней** или **30 дней** (до сегодня).
2. Нажмите **«Составить отчёт»**. Отчёт составляется только по кнопке: один отчёт — один запрос к Claude API, обычно 20–60 секунд.
3. На экране: итог, **проблемы** (важность: важно / средне / мелочь, тема, что не так, факты из сводки) и **предложения**
   (что сделать, как, ожидаемый эффект). **«Скачать Excel»** — листы «ИИ-отчёт», «Проблемы», «Предложения» и «Сводка для ИИ»
   (что именно ушло ИИ), файл `BURAQ_II-hisobot_2026-09-27.xlsx`. **«Печать / PDF»** — как у остальных отчётов.

Что уходит ИИ — сводка, которую сайт собирает сам:
- **доставки и водители** — по отметкам в боте: доставлено / не доставлено и причины, ожидание клиента, отметки дальше
  допустимого от клиента, отметки без фото, незакрытые рабочие дни, точки партии без отметки в боте, начало и конец дня,
  проблемы в пути (только вид: пробка, поломка…), машины без водителя;
- **расходы и машины** — по партиям, машинам и районам: стоимость, компания платит / с клиентов, пробег, загрузка, перегруз,
  рейсы без тарифа, нехватка машин, планы A / B / C против журнала, тарифы и правила планов;
- **качество данных** — клиенты без координат и района, у границы кольцевой, неполные карточки (только сколько каких
  полей не хватает), отгрузки без CBM, KG, мест и машины, BL не из справочника, незакрытые статусы прошедших партий.

Чего ИИ **не получает**: имён клиентов и брендов, телефонов, адресов, получателей, текста водителей о проблемах. Можно:
числа, BL, районы, машины, причины недоставки. Водители — под кодами `DRV1`, `DRV2`…; на экране и в Excel код заменяется
именем только на этом устройстве.

Как устроено:
- запрос идёт через скрипт Google Таблицы, как ИИ-импорт (свойства `ANTHROPIC_API_KEY`, `AI_MODEL`, `EDITOR_TOKEN`, код
  версии 8 и выше) — ключ на сайт не попадает, отчёт составляет только руководитель (вход «только просмотр» кнопки не видит);
- ответ — строго по схеме (итог, до 7 проблем и до 7 предложений); язык отчёта — язык сайта в момент составления;
- каждый вызов — строка «ИИ-отчёт» в листе «ИИ-журнал»;
- последний отчёт хранится на этом устройстве (в браузере) и виден после перезагрузки; в Google Таблицу он не пишется.

ИИ может ошибаться: цифры проверяйте в отчётах «Партия на день», «Расходы», «Автопарк» и «Водители».

## Пакинг-листы: коробки отгрузки

У отгрузки может быть список коробок по пакинг-листу — «Коробки» в окне отгрузки: `60×40×50×12; 80×60×40×3`
(длина × ширина × высота в см × штук; группы через «;», «×12» можно не писать — одна коробка, число штук можно
писать и впереди: «12 шт 60×40×50»). Хранится в Google Таблице — «Yuborishlar» W «Qutilar, sm» (скрипт версии 33;
столбец занят чем-то своим — правка вернётся ошибкой, как у «куда везти»; пока код скрипта ниже 33, коробки живут
только на этом устройстве и в таблицу не попадают — окно отгрузки об этом предупреждает). Пустые «Мест» и CBM при
сохранении заполняются из коробок; в журнале у такой отгрузки «📦 15 кор.».

- **Загрузка из файла** — «📦 Пакинг-листы» в журнале: один или несколько Excel-файлов (.xlsx) из Китая, любой из
  привычных шаблонов (长/宽/高 и «CTN/件数», «cartons size (m)» с L/W/H, «коробка 件数», «箱数» и т. п.): сайт
  находит строку заголовка с длиной, шириной и высотой коробки и столбец с числом коробок, единицы (см, м, мм)
  распознаёт по заголовку и по значениям (сверяясь со столбцом объёма, если он есть), BL — по ячейке «Customer
  shipping mark / 客户唛头», столбцу «Mark» или имени файла. Шапка в несколько строк (число коробок ниже размеров) и шапка
  без названий (размеры и число коробок находятся по объёму: длина × ширина × высота = CBM строки) тоже читаются.
  Партия в окне подбирается по BL из файлов (если в открытой партии их нет — та, где совпадений больше).
  **Через ИИ** — переключатель «Читать ИИ» в окне: «автоматически» (по умолчанию) — всё, что не разобралось по правилам,
  а также PDF и фото пакинг-листа (снимок из WeChat, скан) Claude читает сразу; «по кнопке» — только по «🤖 Прочитать ИИ»
  у файла. Запрос идёт через скрипт таблицы, как ИИ-импорт (те же ключ, секрет редактора и «ИИ-журнал»; `js/packing.js`
  → `aiRequest`/`fromAi`): Excel — текстом ячеек, PDF — целиком, фото — картинкой не больше 1568 px; ответ по схеме
  (размеры, единицы, число коробок, маркировки, итог) проверяется так же, как разбор по правилам (1–500 см, сверка с итогом
  документа), у строки видно «прочитал ИИ · модель · токенов». В окне — файл →
  BL партии (можно поправить) → коробок и м³
  против «мест» и CBM журнала; «Применить» записывает коробки отгрузкам партии (у BL с несколькими строками —
  в самую большую). Старый `.xls` (Excel 97–2003) читается так же, как `.xlsx` (`js/xls-biff.js`).
- **Планы** проверяют каждый рейс, где у точек есть коробки: укладка в кузов машины (размеры кузова — из карточки
  машины, иначе типичные для вида) стенками от кабины к дверям, коробки одного размера столбиками, с поворотом; точки
  в порядке разгрузки (последняя — к кабине), точка без списка — блок на весь поперечник по её объёму с воздухом.
  В шапке рейса — «📦 по коробкам: 3,8 из 4,2 м» или красным «не помещается: 5 кор.» / «не проходит в кузов» (коробка
  больше сечения кузова). Сам план по-прежнему строится по объёму (с полезным процентом) — лишние точки переносят
  вручную («Планы» → правка).
- **3D** рисует настоящие коробки своих размеров (точка без списка — полупрозрачный блок), «не помещается N кор.» —
  за дверями.
- Код: `parseBoxes`/`boxesText` в `js/logi-engine.js`, укладка `packBoxes` и `layout` в `js/logi-viz.js`, разбор
  файлов — `js/packing.js`; тесты `tests/boxes.test.mjs`, `tests/packing.test.mjs`.

## Визуализация загрузки (3D)

Вкладка «Визуализация» показывает рейсы плана в 3D: все машины партии рядом или один рейс
(кнопка «Загрузка 3D» у рейса во вкладке «Планы» открывает его сразу).

- **Две партии:** рядом с выбором партии — «+ вторая партия», как во вкладке «Планы» (выбор общий): 3D показывает план
  на обе партии, в сводке — «Две партии: 04.10.2026 + 06.10.2026», у точек рейса — дата их партии («BL-12 · 04.10»).

- **Груз:** размеров мест в данных нет, поэтому груз каждой точки раскладывается кубиками по объёму
  (CBM). Порядок — как при разгрузке: последнюю точку грузят первой к кабине, точка 1 у дверей.
  Груз сверх кузова (допуск плана B) показан за дверями полупрозрачным.
- **Кузов:** Labo — бортовой, по данным производителя (UzAuto): 1,94 × 1,33 м, борт 0,29 м, колёсная база
  1,84 м; высота груза — из объёма Labo во «Тарифах» (3 м³ ≈ 1,16 м). Changan, Gazel и Kamaz — фургоны
  с типичными шириной и высотой, длина — из объёма во «Тарифах».
- **Машины:** у каждой марки своя кабина. Gazel — с коротким капотом, Changan — полукапотная, Labo и Kamaz —
  кабина над двигателем. У всех колёса с дисками, фары, зеркала и бампер. Раскраска — в фирменных цветах:
  белая кабина, синий низ, красная полоса и логотип BURAQ на дверях; у Kamaz кабина синяя с белым логотипом.
  Стенки фургона — как тонированное стекло, груз виден. Мягкие тени и отражения.
- **Качество: высокое / обычное** — кнопка над сценой (рядом с «3D · Сбоку · Сверху · Сзади»), выбор запоминается
  на устройстве. Пока не выбрано, на компьютере (экран от 700 px, мышь, от 4 ядер и 4 ГБ памяти, настоящая видеокарта)
  включается высокое, на телефоне и при программной отрисовке — обычное. Высокое качество:
  - краска под лаком, хром (диски, решётка, ободки фар, зеркала, ручки, запоры дверей);
  - точёные колёса: шина с боковиной и канавками протектора, диск с гайками, отверстиями и колпаком; у Kamaz задние
    колёса спаренные;
  - кабина: шов двери, дворники, решётка с планками, ходовые огни и противотуманки, номер; боковые окна прорезаны —
    за тонированным стеклом видны сиденья с подголовниками и руль;
  - фургон: петли, запорные штанги с ручками, верхние габариты, фонарь заднего хода, номер, тонкая красная линия по низу;
  - коробки — картон со скотчем сверху и на торцах и наклейкой сбоку (цвет точки сохраняется);
  - разметка стоянки под каждой машиной;
  - эффекты: мягкие тени в щелях (между коробками, под машиной, у колёс — GTAO), свечение фар и фонарей (bloom),
    сглаживание MSAA, чёткость до 2. Фон рассчитан так, чтобы после тона совпасть с фоном сайта.
  Переключение пересоздаёт сцену (сглаживание и эффекты задаются при создании).
- **Кадр:** камера наводится по габаритам каждой машины и подписям, сцена — по центру; в обзоре первый рейс ближе
  к камере, дальние машины видны над ближними.
- **Разгрузка по точкам:** ползунок и ▶ убирают груз выгруженных точек (коробки выезжают через двери);
  нажатие на груз выделяет точку. При открытии рейса груз укладывается по порядку — от кабины к дверям.
- **Плавность:** камера вращается с инерцией и плавно перелетает между видами и рейсами. Шейдеры собираются
  в фоне, а сцена проявляется, когда готова. При уходе с вкладки сцена сохраняется, поэтому при возврате
  открывается сразу. Если в системе включено «Уменьшить движение», всё работает без анимаций.
- **Скорость:**
  - неподвижные детали всех машин слиты в одну сетку на материал: десятки вызовов отрисовки вместо сотен;
  - тени считаются один раз на сцену, а не каждый кадр;
  - груз, земля, резина и рама — с простым быстрым материалом;
  - в обзоре коробки без скруглений (в высоком качестве — со скруглениями);
  - чёткость не выше 1,5 (в высоком качестве — 2) и сама снижается, если устройство не успевает; в высоком качестве
    сначала тени в щелях считаются только в покое (последний кадр движения — с ними), потом снижается чёткость;
  - в высоком качестве подписи рисуются поверх готового кадра, без теней и свечения;
  - на ноутбуке используется мощная видеокарта.
- Раскладка — `LogiViz.layout` в `js/logi-viz.js`, сцену рисует three.js: своя сборка
  `js/vendor/three/three-viz.min.js` (как собрать — в `tools/three-viz-entry.js`), работает и без интернета.

## Язык сайта: узбекский и русский

- **Переключатель UZ / RU** — в шапке рядом с «Аккаунт» и на экране входа (справа вверху). Выбор запоминается
  на устройстве. Пока язык не выбран, сайт открывается по-русски, а если язык телефона или браузера узбекский —
  по-узбекски.
- **Что переводится:** весь текст сайта — вкладки, кнопки, подсказки, сообщения, плашки, окна подтверждения,
  подписи в 3D, отчёты в Excel («Отчёты», «Водители»).
- **Что не переводится:**
  - данные: имена клиентов, адреса, заметки, причины от водителей, заметки ИИ, названия групп и таблиц;
  - файл данных «Скачать Excel» в журнале — листы и столбцы в нём как в Google Таблице.
- **Телеграм-бот** — отдельно: язык водитель выбирает в боте («🌐 Til / Язык»). Сообщения клиентам — на узбекском.

Как устроено: код сайта пишет по-русски, а `js/i18n.js` переводит всё, что появляется на экране, по словарю
`tools/i18n/uz.txt`. При обратном переключении на русский возвращается исходный текст.

**Словарь** — строки «русский<TAB>узбекский» в `tools/i18n/uz.txt`:

- в строке можно ставить метки: `{n}` — число, `{d}` — дата, `{t}` — время, `{w}` — слово, `{s}` — любой текст;
- варианты пишутся в квадратных скобках: `[рейс|рейса|рейсов]`, `[| на {n2} маш.]`.

После правки словаря выполните `node tools/build-i18n.mjs`. Команда соберёт `js/i18n-uz.js` и проверит словарь:

- перевод без кириллицы;
- метки те же, что в русской строке;
- одна строка не переведена двумя способами.

Новая надпись без перевода остаётся на русском. Чтобы найти такие надписи, поставьте в браузере
`localStorage['buraq-i18n-audit'] = '1'`. Сайт останется русским, а строки без перевода накопятся
в `I18N.missing` (в консоли: `[...I18N.missing]`).

## Фирменный стиль

Оформление — по бренд-буку `buraq-brand/BRAND.md`:

- Пять фирменных цветов, все заданы переменными в `css/design-system.css` (`--buraq-*`):
  - тёмно-синий `#0E2E54` — шапка, текст, фон экрана входа;
  - белый `#FFFFFF`;
  - синий `#034CAA` — ссылки и второстепенные акценты;
  - серый `#BFBFBF`;
  - красный `#DE0441` — главные кнопки, стрелки, линия под шапкой.
- Логотип — только файлы из `buraq-brand/logo/`: на синем фоне — белый, на светлом — основной. Иконки приложения
  (`icons/`) — белый логотип на синем.
- Шрифт — Neue Montreal (лицензия BURAQ; `fonts/NeueMontreal-{Regular,Medium,Bold}.woff2`, работает без интернета).
  В нём только латиница, поэтому:
  - узбекский интерфейс и вся латиница, цифры — Neue Montreal;
  - русские буквы и знаки, которых нет в Neue Montreal (³ № ʻ), — Inter (`fonts/inter-*`), браузер подставляет их сам;
  - числа в столбцах таблиц (`tabular-nums`) — Inter: у Neue Montreal нет цифр одной ширины, и столбцы «плясали» бы.
  Шрифты подключены в `css/design-system.css` (`@font-face`, `--font-body`, `--font-num`) и кэшируются в `sw.js`.
  Другие начертания (Light, Italic) не подключены — на сайте не используются.
- Заголовки — капсом, обычной толщины. Кнопки — «таблетки». Над заголовком раздела — тонкая красная стрелка.
- Движение (`css/app.css`, «Плавность»):
  - вкладки и окна появляются плавно, кнопки мягко меняют цвет и слегка «нажимаются»;
  - полоски заполнения растут;
  - новая вкладка открывается сверху;
  - длинный список клиентов рисуется в два кадра, поэтому вкладка появляется сразу;
  - 3D-библиотека загружается заранее, пока сайт простаивает.
  Если в системе включено «Уменьшить движение», анимаций нет.
- Стекло (`css/glass.css`, подключается последним):
  - фон — светлый, с мягкими пятнами тёмно-синего, синего и каплей красного;
  - карточки, таблицы, сводки — матовые белые панели со скруглением и тенью;
  - шапка — тёмно-синее стекло с красной линией снизу, окна — плотное стекло на размытом фоне;
  - размытие — только у шапки, подвкладок и окон. Панели полупрозрачные без размытия: размытие под каждой панелью
    пересчитывалось на каждом кадре прокрутки, и длинные списки дёргались (замер: «Клиенты» — 70 мс на кадр вместо
    16,7 мс). На телефоне панели ещё плотнее;
  - браузер без размытия или «Уменьшить прозрачность» в системе — панели плотные, при печати — белые.
  Новые панели получают стекло классом `glass` (или попадают в общий список в `css/glass.css`).
- Тёмная тема (`css/glass-dark.css`, `js/theme.js`) — стекло по `buraq-brand/DESIGN-GLASS.md`
  (живой пример — `buraq-brand/brandbook.html`):
  - включается кнопкой ☾ / ☀ рядом с UZ / RU (в шапке и на экране входа; на телефоне — в окне «Аккаунт»), выбор
    запоминается на устройстве; пока не выбрана — как в системе (тёмное оформление Windows, macOS, телефона);
  - фон — тёмно-синий с размытыми пятнами синего и красного и лёгким зерном; панели — белый 7–11 % с белой границей
    18 % и бликом по верхней кромке; текст — белый, вторичный — белый 72 %; красный — только акценты и главная кнопка;
  - новых цветов нет: в тёмной теме переопределены токены `css/design-system.css` (`:root[data-theme="dark"]`).
    Поэтому новые цвета в разметке — только через токены: тогда они верны в обеих темах. Для «выделения» —
    `--color-accent-line`, для акцентного текста — `--color-accent-text`, для текста на синем и красном —
    `--color-on-accent`;
  - карты остаются светлыми (подложка карт светлая): метки, их окна и легенда берут цвета из светлых токенов
    (`.tok-light`), подложка слегка приглушена;
  - 3D — тёмно-синяя сцена (`--viz-bg`, `--viz-ink`), при смене темы пересобирается;
  - на экране входа пятна медленно плывут; на рабочих экранах стоят: любая анимация выносит фон в отдельный слой,
    и прокрутка журнала и клиентов шла 27–30 мс на кадр вместо 16,7 (замер). Теперь тёмная прокручивается как
    светлая;
  - печать — всегда светлая.
- Интерфейс для сотрудников — на русском и узбекском (переключатель UZ / RU), тексты для клиентов — на узбекском
  латиницей.

## Установка на телефон

- **Android (Chrome):** откройте сайт, войдите, нажмите «Установить приложение»
  внизу экрана или «⋮ → Установить приложение».
- **iPhone (Safari):** «Поделиться» → «На экран „Домой“».

## Публикация (GitHub Pages)

1. **Settings → Pages → Build and deployment → Source: GitHub Actions**.
2. Сайт собирается workflow `.github/workflows/pages.yml` при каждом пуше в основную ветку репозитория.
   Запустить вручную: **Actions → Deploy site to GitHub Pages → Run workflow**.
3. Адрес: `https://<владелец>.github.io/<репозиторий>/` — сейчас https://buraqceoassistant-ai.github.io/BuraqYetkazish/ (до 12.10.2026 репозиторий назывался `xeeds`).

При каждой сборке service worker получает новую версию кэша. Открытый сайт сам проверяет, нет ли новой версии, —
раз в 30 минут и при возврате в приложение (телефон держит его открытым неделями, а браузер проверяет обновления
только при открытии страницы). Когда новая версия скачалась, слева внизу — «Вышла новая версия сайта · Обновить»:
перезагрузка по кнопке, чтобы не закрыть окно с несохранённым вводом (правки журнала и так хранятся на устройстве).

Всё, что service worker кладёт в кэш (`SHELL` в `sw.js`), должно копироваться на сайт в `pages.yml` — это проверяет
`tests/deploy.test.mjs`. С 15.10 по 19.10.2026 папка `img` (фото автопарка) на сайт не копировалась: новая сборка не
могла поставиться, и у всех, кто уже открывал сайт, оставалась старая версия. Теперь страница, скрипты, стили и данные —
обязательны, а недостающая картинка, шрифт или значок установку новой сборки не останавливают.

## Скорость

Замеры — `perf-probe` на реальных данных и на данных ×10 (1 580 отгрузок, 830 клиентов), процессор замедлен в 4 раза,
как у среднего телефона.
- **Слой перевода** (`js/i18n.js`) отмечал кнопки языка поиском по родителю каждого нового узла — таблица на 800 строк
  перерисовывалась секундами (рост квадратичный). Теперь — один раз на пачку изменений. «Клиенты» ×10: 18,3 → 1,5 с.
- **Клиенты** — по 100 строк и «Показать ещё» (как журнал): поиск и фильтры не перерисовывают всех клиентов.
- **Планы** кэшируются по партии: ключ — её точки с клиентами, настройки и машины. Правка другой партии или обновление
  из таблицы без изменений этой партии не пересчитывают её планы («Расходы» строят планы всех партий периода).
- **Сортировки** BL и машин — одним `Intl.Collator` вместо `localeCompare` с параметрами на каждое сравнение.
- **Меньше загрузки при входе:** узбекский словарь (250 КБ) — только если сайт по-узбекски (по-русски — при нажатии
  «UZ»); код скрипта таблицы (170 КБ) — только на странице «Связь». Для работы без сети оба в кэше service worker.

## Локальный запуск

```bash
python3 -m http.server 8000
# http://localhost:8000
```

На `localhost` service worker отключён, чтобы правки были видны сразу.
Включить для проверки: `http://localhost:8000/?sw=1`.
